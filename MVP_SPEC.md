# MVP: Telegram-бот «Матрица Судьбы»

Техническое задание на первую версию. Цель — к концу вечера получить работающего бота, которого можно дать первым 20–30 пользователям и измерить виральность (K-фактор).

## 1. Суть продукта

Бот считает Матрицу Судьбы по дате рождения. Весь MVP бесплатный:

| Уровень | Что открывается | Условие |
|---|---|---|
| 1. Тизер | 3 главных аркана кратко: личность, таланты, предназначение | Ввод даты рождения |
| 2. Полный общий разбор | Личность, таланты, предназначение, зона комфорта — развёрнуто | Подписка на 1–3 канала |
| 3. Всё остальное | Деньги, отношения, карма, совместимость, прогноз на год, практики, AI | Приглашения друзей |

Платежей, AI-консультанта, карточек-картинок, inline-режима, рассылок и квестов в MVP **нет**. Архитектура должна позволять добавить их позже.

Тон текстов: тёплый, поддерживающий, без обещаний результатов в деньгах, здоровье и отношениях. В /help пометка: «Разбор носит развлекательный характер и предназначен для самопознания».

## 2. Стек

- Python 3.12, aiogram 3.x, режим **long polling** (без webhook)
- PostgreSQL 16 + SQLAlchemy 2 (async, asyncpg) + Alembic
- FSM — MemoryStorage (Redis в MVP не нужен)
- pytest для тестов
- Docker + docker-compose (сервисы `bot` и `db`)
- Настройки через `.env` (pydantic-settings)

## 4. Расчёт матрицы (`services/matrix_calc.py`)

За основу берётся методика Натальи Ладини. Все формулы — в одном модуле, чтобы при расхождении с эталонным калькулятором правка была в одном месте.

**Приведение к аркану:** `reduce(n)` — пока `n > 22`, заменять `n` на сумму его цифр. Результат от 1 до 22.

**Базовые точки** (дата ДД.ММ.ГГГГ):
- A = reduce(день) — личность, «визитная карточка»
- B = reduce(месяц) — таланты
- C = reduce(сумма цифр года) — материальная сфера
- D = reduce(A + B + C) — нижняя точка, основа кармического хвоста
- E = reduce(A + B + C + D) — центр, зона комфорта

**Предназначение:**
- Небо = reduce(B + D), Земля = reduce(A + C)
- Личное предназначение = reduce(Небо + Земля)

**Сферы:**
- Деньги: C и денежный канал reduce(C + E)
- Отношения: H = reduce(C + D) и reduce(H + E)
- Кармический хвост: D, d1 = reduce(D + E), d2 = reduce(D + d1); показывать как `d2-d1-D`
- Прогноз на год: reduce(A + B + reduce(сумма цифр текущего года))

**Совместимость двух людей:** для каждой из точек A, B, C, D, E — reduce(точка_1 + точка_2). Главное число пары — reduce(E1 + E2).

Функция `calculate(birth_date: date) -> Matrix` возвращает dataclass со всеми точками. Функция `compatibility(m1, m2) -> CompatMatrix`.

**Тесты:** минимум 10 дат, включая 29.02, 31-е числа, годы 19xx и 20xx, дни больше 22. После написания тестов вывести таблицу «дата → A, B, C, D, E, предназначение, хвост», чтобы владелец сверил её с онлайн-калькулятором Матрицы Судьбы. Не выдумывать «эталонные» значения из других источников — считать по формулам выше.

## 6. Пользовательский путь

1. **/start** без параметров → приветствие в 2 строки и просьба прислать дату рождения в формате ДД.ММ.ГГГГ.
   **/start r_<code>** → то же + «Тебя пригласил друг, и он дарит тебе открытую сферу „Деньги“».
   **/start c_<code>** → «<Имя> хочет узнать вашу совместимость. Пришли свою дату рождения».
2. **Ввод даты** — валидация (реальная дата, год 1920–текущий). При ошибке — подсказка с примером. Повторно дату можно сменить через /settings.
3. **Тизер** — 3 аркана (A, B, личное предназначение): название + teaser. Кнопки: «🔓 Полный разбор», «💞 Совместимость», «👥 Пригласить друзей».
4. **Полный разбор** — если каналы настроены и пользователь подписан не на все: список каналов кнопками-ссылками + «Я подписался». Проверка через `getChatMember`, подписан = статус `member`, `administrator`, `creator` или `restricted` с `is_member`. Если каналов в БД нет — разбор открывается сразу.
   Разбор: личность (A), таланты (B), предназначение, зона комфорта (E). Ниже — меню закрытых сфер с замком и подписью условия: «🔒 Кармический хвост — пригласи ещё 2 друзей».
5. **Сферы** — каждая открытая сфера показывается отдельным сообщением по кнопке.
6. **Совместимость** — кнопка выдаёт ссылку `c_<code>` и готовый текст для отправки. Когда второй человек ввёл дату:
   - обоим приходит краткая совместимость: главное число пары + текст `compat`;
   - подробная (все 5 точек) — только у того, кто открыл её шкалой;
   - второму человеку сразу предлагается проверить совместимость с кем-то ещё.
7. **Пригласить друзей** — ссылка `r_<code>`, прогресс («Активировано: 2. До кармического хвоста: 1 друг»), список наград по шкале, кнопка «Поделиться» через `https://t.me/share/url?url=<ссылка>&text=<текст>`.

Команды: `/start`, `/matrix`, `/compat`, `/invite`, `/settings`, `/help`, `/deletedata`. Регистрировать через `set_my_commands`. Все главные действия доступны кнопками.

## 7. Рефералка и шкала (`services/referrals.py`)

- У каждого пользователя случайный короткий `ref_code` (8 символов).
- Пригласивший фиксируется **только при первом /start** и больше не меняется. Нельзя пригласить самого себя.
- Ссылка `c_<code>` тоже делает владельца кода пригласившим.
- **Активация** — приглашённый ввёл корректную дату рождения. Только активированные друзья идут в шкалу.
- Пригласившему при активации друга приходит сообщение: «Твой друг рассчитал матрицу! Активировано: N» + что открылось, если достигнут порог.
- Приглашённый сразу получает подарок — сферу «Деньги».
- Антифрод: не больше 20 засчитанных активаций в сутки на одного пригласившего, остальные пишутся, но не засчитываются до ручной проверки.

**Шкала.** Пороги и порядок наград в `config.py`:

```python
REWARD_THRESHOLDS = [1, 2, 3, 5, 7, 10]
REWARD_ORDER = ["money", "relationships", "karma", "compat_full_and_year", "practices", "ai"]
```

Каждый достигнутый порог открывает **следующий ещё закрытый** пункт из `REWARD_ORDER` (так подарок «Деньги» у приглашённого не сгорает). Пункты `practices` и `ai` в MVP открываются, но показывают «Скоро появится — ты получишь доступ первым».

## 8. База данных

| Таблица | Поля |
|---|---|
| users | id, tg_id (unique), username, first_name, birth_date, ref_code (unique), referrer_id, created_at, activated_at, channels_ok_at, is_blocked |
| referrals | id, inviter_id, invited_id (unique), kind (`ref` / `comp`), created_at, activated_at, counted (bool) |
| unlocks | id, user_id, item, source (`gift` / `referral` / `admin`), created_at; unique(user_id, item) |
| compat_pairs | id, user_a, user_b, created_at; unique пары |
| channels | id, chat_id, title, url, is_active, sort_order, joined_count |
| events | id, user_id, name, payload (jsonb), created_at |

События (`events.name`): `start`, `birth_date_set`, `teaser_shown`, `channels_prompt`, `channels_ok`, `full_shown`, `invite_opened`, `share_clicked`, `compat_link_created`, `referral_started`, `referral_activated`, `unlock`, `sphere_opened`.

## 9. Админ-команды (только для ADMIN_IDS)

- `/stats` — за сегодня, 7 дней и всё время: новые пользователи, активированные (ввели дату), прошли каналы, открыли «пригласить», реферальные старты, реферальные активации, доля реферальных пользователей, **K = реферальные активации / активированные пользователи** за период.
- `/channels` — список каналов; `/addchannel <@username или chat_id> <ссылка>` — бот проверяет, что он админ в канале, иначе ошибка; `/delchannel <id>`.
- `/broadcast_test` не нужен — рассылок в MVP нет.

## 10. Надёжность

- Глобальный обработчик ошибок: лог + пользователю «Что-то пошло не так, попробуй ещё раз».
- `TelegramForbiddenError` при отправке → `users.is_blocked = true`.
- `/deletedata` удаляет дату рождения и разблокировки пользователя.
- Логи в stdout.

## 11. Порядок работы

Делать по этапам. После каждого этапа — тесты и короткий отчёт: что сделано, как проверить в Telegram.

1. Каркас: структура, Docker, БД, миграции, /start, ввод и валидация даты.
2. `matrix_calc.py` + тесты + таблица для сверки.
3. `arcana.json` для всех 22 арканов.
4. Тизер, проверка каналов, полный разбор, админ-команды каналов.
5. Рефералка, шкала, подарок, уведомления пригласившему, сферы.
6. Совместимость.
7. События и /stats.
8. README: локальный запуск, деплой на VPS через docker-compose, как добавить бота админом в канал.

Если что-то в задании противоречит само себе или неясно — спросить, а не угадывать. Если этап затягивается, сначала довести до рабочего состояния этапы 1–4: бот с тизером и разбором уже можно отдавать людям.
