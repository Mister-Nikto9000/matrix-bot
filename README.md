# Telegram-бот «Матрица Судьбы» — версия 2

Бот считает Матрицу Судьбы по дате рождения (методика Н. Ладини). Всё бесплатно:

1. **Тизер** — 3 аркана (личность, таланты, предназначение) сразу после ввода даты. Под ним кнопка «🖼 Картинка для сторис».
2. **Полный разбор** — после подписки на каналы (если каналы настроены). Выходит двумя сообщениями (личность и таланты; предназначение и зона комфорта), затем меню сфер.
3. **Сферы** (деньги, отношения, кармический хвост, подробная совместимость и прогноз на год, практики) — за приглашения друзей. «AI-консультант» пока заглушка.
4. **Число дня** — ежедневная подсказка по матрице (рассылка по подписке), **квест дня**: пригласить друга — открыть прогноз на завтра.
5. **Автоворонка** — три напоминания (каждое один раз на человека), **рассылки от админа**, **inline-режим** (`@бот` в любом чате), команда `/matrix` в группах.
6. **Метрики для админа** — воронка, вирусность (K), удержание, каналы, источники трафика, дайджест и алерты.

Платежи Stars и AI-консультант в эту версию не входят.

Техническое задание — [MVP_SPEC.md](MVP_SPEC.md).

Стек: Python 3.12, aiogram 3 (long polling), PostgreSQL 16 (или SQLite для запуска без Docker), SQLAlchemy 2 (async) + Alembic, Docker Compose.

---

## 1. Создать бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
2. Узнайте свой Telegram ID (например, у [@userinfobot](https://t.me/userinfobot)) — он нужен для админ-команд.

## 2. Настройки

```bash
cp .env.example .env
```

Заполните `.env`:

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `ADMIN_IDS` | Telegram ID админов через запятую: `111,222` |
| `DATABASE_URL` | для Docker: `postgresql+asyncpg://bot:bot@db:5432/bot`; для `run.bat` без Docker: `sqlite+aiosqlite:///bot.db` |
| `BOT_USERNAME` | username бота без `@` (если пусто — бот узнает его сам при старте) |

`.env` не коммитится (он в `.gitignore`).

## Быстрый запуск на Windows без Docker

Нужен только Python 3.12+ с [python.org](https://www.python.org/downloads/) (при установке отметьте «Add python.exe to PATH»). База — файл SQLite `bot.db` в папке проекта.

1. Создайте `.env` (см. раздел 2) и укажите в нём SQLite:

   ```
   DATABASE_URL=sqlite+aiosqlite:///bot.db
   ```

2. Дважды кликните `run.bat` (или запустите его из консоли в папке проекта). Скрипт:
   - создаёт `.venv`, если её нет;
   - ставит зависимости из `requirements.txt`;
   - **копирует `bot.db` в `backups/bot-before-v2.db`** (один раз, если база ещё не мигрирована на версию 2);
   - применяет миграции (`alembic upgrade head`);
   - запускает бота (`python -m bot.main`).

3. В консоли должно появиться `Bot @… started (long polling)` и строка `allowed_updates: …` (в ней есть `inline_query` и `chosen_inline_result`). Остановить — `Ctrl+C`.

### Работа без остановок: `run_forever.bat`

Делает то же самое, но после запуска бота сам **перезапускает его через 5 секунд**, если он упал. Лог — `logs/bot.log` (ротация: 5 МБ × 5 файлов, токен и даты рождения в лог не попадают).

> **Отключите спящий режим на ПК** (Параметры → Система → Питание → Экран и спящий режим → «Никогда»), иначе, пока компьютер спит, бот не отвечает и не присылает число дня.

### Резервные копии SQLite

- Перед первой миграцией на версию 2 — `backups/bot-before-v2.db` (делает `run.bat` / `run_forever.bat`; в этой копии ещё лежат старые события с датами рождения — удалите её, когда убедитесь, что всё работает).
- Каждый день бот сам делает `backups/bot-ГГГГММДД.db` встроенным механизмом `sqlite3 backup` (безопасно при работающем боте) и хранит 7 последних. Дата последней копии видна в `/health`.
- Восстановление: остановить бота, заменить `bot.db` нужной копией, запустить.
- Компьютер должен быть включён, пока бот работает. Для постоянной работы используйте VPS (раздел 4).

## 3. Локальный запуск (Docker Desktop)

Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/), затем в папке проекта:

```bash
docker compose up --build
```

При старте контейнер `bot` сам применяет миграции (`alembic upgrade head`) и запускает long polling. Логи — в консоли (stdout). Остановить — `Ctrl+C`, данные БД сохраняются в volume `pgdata`.

Проверка: напишите боту `/start` и пришлите дату, например `07.03.1994`.

## 4. Деплой на VPS

Подойдёт любой VPS с Ubuntu 22.04+ и 1 ГБ RAM. Webhook и домен не нужны — бот работает через long polling.

```bash
# 1. Установить Docker
curl -fsSL https://get.docker.com | sh

# 2. Скопировать проект (git clone или scp) и перейти в папку
cd matrix-bot

# 3. Создать .env (см. раздел 2)
cp .env.example .env && nano .env

# 4. Запустить в фоне
docker compose up -d --build

# Логи
docker compose logs -f bot
```

Обновление: залить новые файлы и выполнить `docker compose up -d --build` — миграции применятся автоматически.
Сервисы перезапускаются сами (`restart: unless-stopped`), в том числе после перезагрузки сервера.

Резервная копия БД (PostgreSQL бэкапится средствами самой СУБД; встроенные ежедневные копии бота работают только для SQLite):

```bash
docker compose exec db pg_dump -U bot bot > backup.sql
```

**Обновление с версии 1 на версию 2:** сделайте `pg_dump` (команда выше), затем `docker compose up -d --build` — миграции `0004`–`0008` применятся автоматически и не удаляют данные (новым колонкам `users` проставляются значения по умолчанию, источник существующих пользователей — `ref` или `organic`). Планировщик, дайджест и алерты стартуют вместе с ботом.

> Важно: FSM хранится в памяти. После перезапуска бота пользователи, которые были на шаге «пришли дату», просто присылают дату ещё раз — бот её примет. Пара для совместимости при этом не теряется (восстанавливается из БД).

## 5. Каналы

ID и ссылки вводить не нужно — бот всё делает сам. Все кнопки и пересылки работают только для аккаунтов из `ADMIN_IDS`; сначала напишите боту `/start`, иначе он не сможет вам написать.

### Подключить канал

**Новый канал.** Откройте канал → **Управление каналом → Администраторы → Добавить администратора** → найдите бота. Включите ему право **«Пригласительные ссылки»** — без него бот не создаст ссылку для входа, а в канале с заявками не увидит заявки.

Бот сразу пишет всем админам: «Меня добавили админом в канал «…». Подключить его к обязательной подписке?» — и три кнопки:

- **✅ Обычный вход** — бот создаёт пригласительную ссылку «Матрица Судьбы» без заявки;
- **📨 Вход по заявке** — ссылку с заявкой на вступление;
- **Не подключать**.

В ответ: «Канал «…» подключён: {режим}. Ссылка: …». Ссылка сохраняется в боте, её видят пользователи на шаге «подпишись».

**Канал, где бот уже админ.** Перешлите боту любой пост из канала. Если бот там админ — появятся те же кнопки; если нет — бот подскажет, что сделать.

Если не хватает права «Пригласительные ссылки», бот скажет об этом и канал не подключит — включите право и нажмите кнопку ещё раз. Если канал уже подключён, бот покажет текущие настройки и предложит сменить режим.

**Бота сняли с админов или удалили из канала** — канал выключается, а админам приходит сообщение «Меня убрали из админов канала «…» — проверка подписки на него выключена». Чтобы вернуть: снова сделайте бота админом и выберите режим.

### Управление: /channels

Каждый канал — отдельным сообщением с кнопками:

| Кнопка | Что делает |
|---|---|
| **✅ Вкл / ⛔ Выкл** | включить или выключить проверку подписки на канал |
| **Режим: обычный / заявка** | сменить режим входа; бот создаёт новую ссылку |
| **Автоодобрение: вкл / выкл** | только для входа по заявке: бот сам одобряет заявки |
| **⬆️ Вверх / ⬇️ Вниз** | порядок каналов на экране подписки |
| **🗑 Удалить** | убрать канал из подписки (с подтверждением) |

Если каналов нет — полный разбор открывается сразу. Рекомендуется 1–3 канала.

### Вход по заявке

Пока заявка не одобрена, Telegram считает пользователя не подписанным. Поэтому бот сам принимает заявки (апдейт `chat_join_request`) и **засчитывает поданную заявку как подписку** — одобрения ждать не нужно. Пользователь увидит кнопку «📨 Подать заявку: …» и пояснение «Достаточно отправить заявку — одобрения ждать не нужно». Засчитываются только заявки, поданные после подключения канала.

По умолчанию бот заявки **не одобряет** — их одобряете вы в канале. Чтобы бот одобрял сам, включите «Автоодобрение» в `/channels`.

### Старые команды

Продолжают работать: `/addchannel <@username или chat_id> <ссылка> [request]` — подключить канал со своей ссылкой, `/approve <id> on|off` — автоодобрение, `/delchannel <id>` — удалить.

## 7. Рефералка и антифрод

- Пороги и порядок наград — в [bot/config.py](bot/config.py): `REWARD_THRESHOLDS`, `REWARD_ORDER`. Каждый достигнутый порог открывает следующий ещё закрытый пункт.
- Приглашённый по ссылке `r_…` сразу получает сферу «Деньги».
- Больше `DAILY_ACTIVATION_LIMIT` (20) активаций за последние 24 часа на одного пригласившего не засчитываются (`referrals.counted = false`). Проверить и засчитать вручную:

```bash
docker compose exec db psql -U bot bot
```

```sql
-- кто упёрся в лимит
SELECT inviter_id, count(*) FROM referrals
WHERE activated_at IS NOT NULL AND counted = false GROUP BY inviter_id;

-- засчитать активации пригласившего с users.id = 42
UPDATE referrals SET counted = true
WHERE inviter_id = 42 AND activated_at IS NOT NULL AND counted = false;
```

Награды за засчитанные вручную активации откроются при следующей активации друга этого пользователя.

## 8. Тексты и формулы

- Тексты интерфейса — [bot/content/messages.py](bot/content/messages.py) (в том числе рассылки, числа дня, квесты, inline и /broadcast). Служебные отчёты админа (`/stats`, `/user`, `/health`) оформлены прямо в `bot/handlers/admin_*.py`.
- Тексты 22 арканов — [bot/content/arcana.json](bot/content/arcana.json). Поля: `teaser` (тизер), `personality`, `talents`, `purpose`, `comfort` (полный разбор: ~700 / ~700 / ~750 / ~400 символов), `day` (число дня), `practice` (практика недели), `money`, `relationships`, `karma`, `compat`, `year`. Объём полей полного разбора проверяет `tests/test_arcana_lengths.py`; первое предложение `purpose` должно быть законченной мыслью — оно идёт в тизер, если аркан повторяется. Любое поле может быть строкой или списком вариантов: вариант выбирается стабильно по пользователю (для совместимости — по паре), один человек всегда видит один и тот же текст.
- **Обращение по роду.** Перед датой бот спрашивает «Как к тебе обращаться?» (👩 Девушка / 👨 Парень); старых пользователей без выбора спрашивает перед первым разбором. Слова, зависящие от рода, в arcana.json и messages.py записаны шаблоном `{мужская|женская}`: `Ты {энергичный|энергичная}`, `указал{|а}`. Формы подставляются при отправке (`bot/services/gender.py`); если пол не выбран — женская. В тексте про другого человека берётся его пол. Новые тексты пишите сразу с шаблонами; проверка мужских форм вне шаблонов (в `arcana.json` и `messages.py`): `python -m scripts.check_gender`.
- Описание бота в профиле — `BOT_DESCRIPTION` и `BOT_SHORT_DESCRIPTION` в messages.py, обновляется при каждом запуске.
- Пример всех сообщений для 07.03.1994 — [SAMPLE_OUTPUT.md](SAMPLE_OUTPUT.md). Пересобрать: `python -m tests.make_sample_output`.
- Все формулы расчёта — [bot/services/matrix_calc.py](bot/services/matrix_calc.py). Если значение расходится с эталонным калькулятором, правка делается только там; тесты в `tests/test_matrix_calc.py` нужно обновить вместе с формулой.

## 9. Число дня, пуши и квесты

**Число дня** = аркан `reduce(личность + reduce(день) + reduce(месяц))` для сегодняшней даты по Москве (`personal_day` в `matrix_calc.py`). Текст — поле `day` в `arcana.json`. После полного разбора бот предлагает «☀️ Присылать число дня» и время; то же — в `/settings`. Рассылка идёт каждую минуту планировщиком внутри бота (без внешних зависимостей), не быстрее 20 сообщений в секунду; `TelegramRetryAfter` пережидается, `TelegramForbiddenError` помечает пользователя `is_blocked`. Один пуш числа дня в сутки на человека гарантируется таблицей `push_log`. Если бот был выключен, подписчики получат число дня после запуска, но не позже чем через 2 часа после выбранного времени.

В конце сообщения — кнопки «Мой прогноз на завтра 🔒 / открыть» и «Пригласить друга».

**Квест дня** (таблица `quests`): «Пригласи 1 друга до 23:59 — откроем прогноз на завтра». Показывается в `/invite` и в числе дня. Прогресс — засчитанные активации друзей за московские сутки. При выполнении пригласивший получает сообщение «Квест выполнен» и разовый доступ к тексту `day` для завтрашней даты (кнопка «Открыть прогноз на завтра»).

**Автоворонка** — каждый пуш уходит человеку один раз (`push_log`, unique по пользователю и виду):

| Вид | Когда |
|---|---|
| `teaser_2h` | через 2 часа после тизера, если каналы не пройдены («Твой полный разбор готов, осталось подписаться») |
| `full_24h` | через 24 часа после полного разбора, если нет приглашённых («Узнай совместимость с близким человеком») |
| `inactive_3d` | через 3 дня без заходов («Число дня и закрытая сфера ждут») |
| `friend` | друг активировался (с кнопкой открыть сферу; если выполнен квест — ещё и прогноз на завтра) |

Ограничения: не больше **2 пушей в сутки** на человека (считаются все пуши, включая число дня; число дня и «друг активировался» не блокируются лимитом), **тихие часы 23:00–09:00 МСК** (отложенное уходит после 09:00), не пишем заблокировавшим и тем, у кого `notify_marketing = false` (`/stop`). Окна давности защищают от «пробуждения» старых пользователей после обновления: `teaser_2h` — не старше 48 ч, `full_24h` — 72 ч, `inactive_3d` — не больше 14 дней без заходов. Каждый пуш с кнопкой; нажатие пишет `push_clicked` в `events` и `clicked_at` в `push_log`.

## 10. Метрики для админа

Всё считается по **московским суткам** (`TIMEZONE` в `bot/config.py`): «сегодня» и «вчера» — это Москва, а не UTC. Время в базе хранится в UTC.

`/stats` — одно сообщение, которое листается кнопками (период × раздел):

- **Сводка** — новые, активированные и % активации, заблокировали бота, DAU / WAU / MAU (от последнего дня периода, по таблице `daily_activity`), доля девушек и парней, спарклайны за 14 дней (`▁▂▃▄▅▆▇█`) по новым и активированным, ошибки за 7 дней.
- **Воронка** — `/start` → ввёл дату → тизер → нажал «Полный разбор» → прошёл каналы → увидел разбор → открыл «Пригласить» → нажал «Поделиться» → реферальный старт → реферальная активация; для каждого шага число, % от предыдущего и % от старта (уникальные пользователи, у которых событие случилось в периоде).
- **Вирусность** — **K = реферальные активации / активированные пользователи** (отдельно по ссылкам `r_` и `c_`), приглашений на приглашающего (среди открывших «Пригласить»), конверсия старт → активация по приглашениям, доля пришедших по рефералке, медиана времени от активации пользователя до первого активированного друга, inline-шеринг по карточкам.
- **Удержание** — D1 / D7 / D30 по когортам дня регистрации (таблица последних 14 когорт по `daily_activity`); «—» означает, что срок ещё не наступил.
- **Каналы** — по каждому каналу: сколько раз показывался, сколько прошло, конверсия, заявки, сколько людей застряли на подписке больше 24 часов.
- **Контент** — открытия сфер, топ арканов личности и предназначения, распределение по десятилетиям рождения (без отдельных дат), совместимость: создано ссылок, завершённых пар, % завершения.
- **Рассылки** — подписчики числа дня, по каждому виду пуша «отправлено / заблокировали / нажатий», рассылки админа, квесты (показан / выполнен / %).
- **Источники** — по каждому `source`: пользователи, % активации, % прошедших каналы, K, D1.
- **Антифрод** — незасчитанные активации, приглашающие с более чем 10 активациями за сутки, аккаунты без username.
- **Ошибки** — необработанные ошибки по дням (таблица `errors`).

**Источники трафика.** Ссылка вида `https://t.me/<бот>?start=s_<тег>` пишет тег в `users.source` при первом `/start`. Для `r_…` и `c_…` источник `ref`, без параметра — `organic`. Ссылку делает команда `/link <тег>`.

**Утренний дайджест** — каждому из `ADMIN_IDS` в 09:00 МСК: вчерашние новые, активированные, K, доля реферальных, прошли каналы, ошибки и разница с позавчера, D1 вчерашней когорты (на 09:00 день ещё идёт) и D1 когорты позавчера. Отключается командой `/digest`.

**Алерты** админам (каждого типа не чаще раза в час): бот перестал быть админом активного канала (проверка при запуске и каждые 5 минут), больше 20 ошибок за час, K за последние 24 часа упал ниже половины среднего за 7 дней (только если активированных за сутки больше 20).

## 11. Рассылки от админа

1. `/broadcast` → пришлите текст одним сообщением (оформление Telegram сохраняется; если его нет — текст считается HTML, набранным руками; формы рода — `{рад|рада}`, подставятся по полу получателя).
2. Бот покажет предпросмотр и сегменты с числом получателей: [Все активированные] [Не прошли каналы] [Без приглашённых] [Девушки] [Парни] и по кнопке на каждый подключённый канал — «📣 Подписчики канала: …» (пользователи бота, которые сейчас подписаны на этот канал; бот проверяет это через getChatMember, для закрытых каналов поданная заявка считается подпиской, проверка занимает до пары минут на тысячи пользователей; бот должен быть админом канала). Telegram не отдаёт список подписчиков канала, поэтому написать можно только тем, кто сам запускал бота. Во всех сегментах — только активированные, не заблокировавшие бота и не выполнившие `/stop`.
3. [📩 Отправить тест мне] → [🚀 Запустить] → подтверждение.
4. Отправка идёт в фоне не быстрее 20 сообщений в секунду, прогресс обновляется по ходу, есть кнопка «Остановить»; в конце — отчёт (отправлено, заблокировали, ошибки). История и статистика — таблица `broadcasts`, команда `/broadcasts`, раздел «Рассылки» в `/stats`.

## 12. Inline-режим, группы, картинки

- **Inline.** В @BotFather: `/setinline` (подсказка, например «Мой аркан») и **`/setinlinefeedback` → Enabled (100%)** — без этого бот не получит `chosen_inline_result` и метрика inline-шеринга будет пустой. `@бот` в любом чате показывает карточки «Мой аркан», «Число дня» (кнопка «Рассчитать свою матрицу» с реферальной ссылкой `r_…`) и «Проверить совместимость» (ссылка `c_…`). Без даты рождения — одна карточка «Сначала рассчитай свою матрицу». В карточки не попадает дата рождения.
- **Группы.** `/matrix` в группе — сообщение с кнопкой-ссылкой «Узнать свой аркан» (реферальный код того, кто вызвал; не чаще раза в 30 секунд на чат). Бот ничего не разбирает в группе и даты не собирает; людей, просто писавших в группе, пользователями бота не считает. Режим приватности (`/setprivacy`) менять не нужно: команды в группах работают и так.
- **Картинка для сторис.** Кнопка под тизером присылает PNG 1080×1920 (Pillow): номер и название аркана личности, фраза, ссылка на бота; подпись содержит реферальную ссылку. Шрифт DejaVu Sans с кириллицей лежит в `bot/assets/fonts/` (лицензия рядом).

## 13. Приватность

- Точная дата рождения хранится только в `users.birth_date` и не попадает в `events`, логи, отчёты, `/export` и карточку `/user` (там — год). Миграция `0008` стёрла даты из ранее записанных событий `birth_date_set`.
- `/deletedata` удаляет дату, обращение, открытые сферы, `push_log`, `quests` и `daily_activity` пользователя; остаётся счётчик «сколько раз удаляли» (виден в `/health`).

## 14. Тесты

Нужен Python 3.12+:

```bash
python -m venv .venv
.venv/Scripts/activate        # Windows; на Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
pytest
```

Тесты не требуют Telegram: расчёт матрицы, шкала наград, сквозные сценарии (реальный диспетчер aiogram + фейковый Bot API + SQLite), проверка, что миграции совпадают с моделями и генерируют корректный SQL для PostgreSQL, запуск `bot.main.main()` в отдельном процессе.

Прогон тех же тестов на PostgreSQL (нужен работающий сервер):

```bash
TEST_DATABASE_URL=postgresql+asyncpg://bot:bot@localhost:5432/bot pytest --ignore=tests/test_migrations.py --ignore=tests/test_startup.py
```

Каждый тест пересоздаёт схему в этой базе — не указывайте рабочую БД.
